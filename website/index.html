01 / The language

A language still taking shape

Underscore is being built incrementally. The project focuses on syntax that makes operations visible at a glance, a compiler pipeline with lexing, parsing, semantic analysis, and code generation, and a standard library that can grow without hiding its behavior.

Readable structure

Functions, conditionals, and loops use recognizable keywords and explicit blocks.

Visible pointers

Pointer declaration and dereferencing use distinct operators instead of an implicit-looking type annotation.

C as a backend

The current compiler emits C and uses a native runtime for selected standard-library calls.

02 / Syntax at a glance

Some of the core ideas

->

Pointer declaration

The arrow belongs next to the variable name to make the pointer relationship visible.

int score = 20
int ->pScore = @score
io.out(<-pScore)
retreat

Return from a function

A function declares its result type; retreat returns the result to its caller.

int twice(int value) <void> {
    retreat value * 2
}
during

Condition-based loop

Loops and branches use explicit conditions and brace-delimited blocks.

int i = 0
during (i < 3) {
    io.out(i)
    i++
}

04 / Project status

Early development, documented honestly

The compiler, language syntax, and runtime are evolving together. A token or syntax form being recognized does not mean every backend behavior is complete. The documentation distinguishes working native calls from designs that still need firm contracts.

What to expect

Use the compiler branch and its smoke tests to evaluate the current implementation. Use the syntax and library references to see what is supported, what is experimental, and what remains planned.
